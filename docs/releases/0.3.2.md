# v0.3.2 发布与回退记录

发布日期：2026-08-22

## 版本边界

- `v0.3.0`：市场锚定与战术单平，Android versionCode 6。
- `v0.3.1`：单场平局对冲，Android versionCode 7。
- `v0.3.2`：多平独立线路组合，Android versionCode 8。
- 三个版本分别使用 Git 标签固定，回退时不要逐文件手工撤销。

## 策略变更

1. 用户预算按每注2元换算为完整14场线路数，不再先构造一个矩形复式主票再分出单场对冲。
2. 每场可选赛果仍严格来自模型原始建议；组合器不把预算压缩结果伪装成模型判断，也不会添加模型已排除的赛果。
3. 模型建议中所有平局按该场候选赛果内的归一化概率分配目标线路数，实际生成结果必须达到每一场的目标配额；当预算足以买完全部唯一组合时，目标按有限组合空间的数学上限调整。
4. 在满足各场平局配额后，优先保留联合概率较高的线路，同时增加多平同线组合，并记录任意两个候选平局共同出现的最低线路数。
5. 每条线路完整列出14个赛果，线路互不重复，总成本不超过预算。旧版 `draw_hedge` 字段仅为历史快照兼容保留，不再由新策略生成。

## 新增数据字段

- `TicketPlan.line_portfolio`：完整线路、平局配额、实际成本、多平线路数和候选平局两两同线最低数。
- API `line_portfolio.draw_coverages`：每场候选平局的概率、目标线路数、实际线路数和覆盖比例。
- API `line_portfolio.lines`：线路编号、14场赛果、票面文本和联合概率。
- 复盘：最佳线路命中数、是否存在14/14线路、实际平局总数，以及所有实际平局同时出现的线路数。

## 26108 回放验收基线

- 输入快照：`reports/history/items/20260821210046-26108-analysis.json`
- 预算上限：500元
- 完整线路：250条，互不重复，总成本500元
- 模型候选平局：12场，全部达到目标配额
- 至少包含两个候选平局的线路：133条
- 任意两个候选平局共同出现：最低33条
- 实际平局：第4、5、11场；三个实际平局共同出现：24条线路
- 最佳线路：命中11/14，没有14/14完整命中

另以本地12个完整期次分别使用2、10、50、128、500、2000元预算做72组压力回放，所有组合均满足不超预算、线路互不重复、每一个候选平局实际线路数不低于目标线路数。

这里需要区分两个问题：实际三个平局已经被同一线路覆盖，因此不是“预算压缩舍弃平局”；整票仍未命中，是因为模型原始建议在第13场只选择 `3/1`，实际赛果为 `0`，同时其他场次组合也有偏差。线路组合器只负责在预算内组合模型允许的赛果，不能补救模型本身排除的结果。

## 回退方法

推荐先保留当前分支，再从目标标签建立回退分支：

```powershell
git switch -c rollback/0.3.1 v0.3.1
```

需要回到0.3.0时：

```powershell
git switch -c rollback/0.3.0 v0.3.0
```

Android 从versionCode 8降级到7或6通常需要允许降级；调试签名一致时可执行：

```powershell
adb install -r -d football-lottery-agent-v0.3.1-debug.apk
```

执行App降级前应先备份应用私有目录中的历史分析与复盘文件；不要通过卸载App来降级，否则可能清除这些数据。
